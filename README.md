# 波兰铁路游戏知识库（文档站）

基于 Docusaurus 3 的**多实例 × 多语言**文档站。

内容按**游戏**分成 5 个互相独立的 docs 实例，每个实例有自己的源目录、路由前缀、侧边栏与 i18n 目录：

| 游戏 | 源目录 | 路由前缀 | 插件实例 id |
| --- | --- | --- | --- |
| SimRail | `docs/simrail/` | `/simrail` | `simrail` |
| Maszyna | `docs/maszyna/` | `/maszyna` | `maszyna` |
| TD2 | `docs/td2/` | `/td2` | `td2` |
| ISDR | `docs/isdr/` | `/isdr` | `isdr` |
| TPF2 | `docs/tpf2/` | `/tpf2` | `tpf2` |

- 语言：默认简体中文（`zh-Hans`），附加英文（`en`，目前仅占位 / 预留）
- 实例清单集中在 `docusaurus.config.js` 顶部的 `games` 数组，增删游戏改那里即可

## 常用命令

开发预览：

```bash
npm install     # 安装依赖
npm run start   # 默认 http://localhost:3000/
```

检查生产构建：

```bash
npm run build   # 输出到 build/
npm run serve   # 本地检查生产构建，默认 http://localhost:3000/
```

其它：

```bash
npm run check-i18n   # 校验译文完整性（CI 门禁）
```

## 目录结构

```
docs/
  simrail/     SimRail 实例源目录
  maszyna/     Maszyna 实例源目录
  td2/         TD2 实例源目录
  isdr/        ISDR 实例源目录
  tpf2/        TPF2 实例源目录
sidebars/      每个实例一个侧边栏（simrail.js … tpf2.js）
src/
  components/  站点自定义组件（如 Collapse）
  theme/       主题覆写（如 MDXComponents.js）
  css/         自定义样式
i18n/en/       英文译文，按插件实例分子目录
               如 docusaurus-plugin-content-docs-simrail/
scripts/       维护脚本
```

新增一篇文档：往对应游戏的源目录里加 `.md` 即可，侧边栏是 `autogenerated`，
会自动出现；顺序用 frontmatter 的 `sidebar_position` 控制。

## 编写文档（Markdown / MDX）

### 新建一篇文档

1. 在对应游戏的源目录下新建 `.md` 文件（如 `docs/simrail/`），文件头写 frontmatter：

   ```md
   ---
   title: 机车车辆
   description: SimRail 机车车辆一览
   tags: [车辆]
   sidebar_position: 2
   ---
   ```

2. 侧边栏是 `autogenerated`，新文件会自动出现，不用改 `sidebars/`。
   要手动控制顺序或分组时，再编辑 `sidebars/<游戏>.js`。

3. 标题后加 `{#anchor}` 可以固定锚点，避免改动标题时链接失效：

   ```md
   ## 环境要求 {#requirements}
   ```

### 折叠面板：`Collapse`

站点内置了全局组件 `Collapse`（源码在 `src/components/Collapse/`，已在 `src/theme/MDXComponents.js` 注册），**无需 import，直接写标签**：

```mdx
<Collapse title="点击展开：环境要求">

- Node.js >= 18
- npm / yarn / pnpm 任一

</Collapse>
```

面板内容支持完整的 Markdown，可以放列表、表格、代码块。

常用写法：

```mdx
<Collapse title="默认展开" defaultOpen>
面板初始就是展开状态。
</Collapse>

<Collapse title="带图标" icon="🚧">
图标是标题栏的前置节点，已设 aria-hidden。
</Collapse>
```

属性：

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `title` | `ReactNode` | — | 标题栏内容，必填 |
| `children` | `ReactNode` | — | 面板内容，支持 Markdown |
| `defaultOpen` | `boolean` | `false` | 初始是否展开（非受控） |
| `open` | `boolean` | — | 受控展开状态，传入后组件变为受控 |
| `onChange` | `(open: boolean) => void` | — | 展开状态变化回调 |
| `icon` | `ReactNode` | — | 标题前的图标 |
| `className` | `string` | — | 附加到面板根元素的类名 |
| `contentClassName` | `string` | — | 附加到内容容器的类名 |

实现要点（改样式或排查问题时有用）：

- 高度过渡：内容容器固定 `overflow: hidden`，内联 `height` 在「实测内容高度」与 `0` 之间切换，配 `transition: height 0.24s ease`。首次渲染即展开时用 `height: auto`，避免挂载瞬间播放一次动画。
- 跟随内容变化：`ResizeObserver` 观察不受高度约束的内层元素，字体加载、图片渲染、窗口缩放后重新测量。
- 无障碍：标题栏是真正的 `button`（`aria-expanded` / `aria-controls`），内容区是 `role="region"` 并用 `aria-labelledby` 关联标题；收起时加 `inert` 移出 Tab 顺序（不能用 `hidden`，会打断过渡）。`Enter` / `Space` 可切换。
- 命中 `prefers-reduced-motion: reduce` 时关闭动画。

### MDX 注意事项

- **标签要独占一行，且和内容之间留空行**，否则整段会被当成普通文本。
- **内容不要缩进**。MDX/Markdown 里 4 个空格缩进会被解析成代码块。
- 正文里的 `{` `}` 会被当作 JSX 表达式求值，需要写成 `\{` 或用反引号包起来。
- 在正文里提到组件名时要用反引号（`` `<Collapse>` ``），直接写会被当成真实标签去渲染。
- 表格单元格里同样要用反引号包裹 `<Collapse` 这类内容。

### 多语言：英文目前是占位 / 预留

站点已配好 i18n（`i18n.defaultLocale` 为 `zh-Hans`，附加 `en`），但**现阶段英文不是必须交付的内容**，只作占位与预留。每个游戏实例有各自的译文目录：

```
i18n/en/docusaurus-plugin-content-docs-simrail/current/   # 对应 docs/simrail/
i18n/en/docusaurus-plugin-content-docs-maszyna/current/   # 对应 docs/maszyna/
...（td2 / isdr / tpf2 同理）
```

- 中文版（`docs/<游戏>/`）是唯一需要维护的版本，**新增文档不必同步英文译文**。
- 将来要正式做英文，按相同路径建文件即可。

自查译文情况：

```bash
npm run check-i18n                  # 缺失译文只列出清单，不计入失败
STRICT_I18N=1 npm run check-i18n    # 缺失译文视为失败（英文转正后再启用）
```

### 本地预览

- **开发预览**：`npm run start`，默认 `http://localhost:3000/`；端口被占用时加 `npm run start -- --port 3001` 指定。
- **检查生产构建**：先 `npm run build` 再 `npm run serve`。构建会为每种语言各输出一份，这是同时检查中文（`/`）和英文（`/en/`）的方式。

两个注意点：

1. **不要在 `docusaurus start` 运行时跑 `npm run build`**。两者共用 `.docusaurus/` 目录，并发执行会把开发服务器的内容注册表写成生产态，导致所有文档页报 `Cannot read properties of undefined (reading 'id')`。真出现了就停掉 dev、删掉 `.docusaurus/` 再重启。
2. 开发服务器一次只加载一种语言（默认 `zh-Hans`）。需要英文开发预览用 `npm run start -- --locale en`，此时整站会挂到 `/en/` 下。

## 部署

推送到 `main` 后由 `.forgejo/workflows/docs.yml` 自动完成：译文检查 → `npm run build` → **FTP 上传**到 `https://wiki.plrail.com/`。

需要在仓库 **Settings → Actions → Secrets and variables** 里配置：

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `FTP_USER` | secret | FTP 用户名 |
| `FTP_PASSWORD` | secret | FTP 密码 |
| `FTP_HOST` | variable | FTP 主机 |
| `FTP_PORT` | variable | 可选，默认 21 |
| `FTP_REMOTE` | variable | 可选，远端目录，默认站点根目录 `/` |
| `FTP_TLS` | variable | 可选，`0` = 明文 FTP；默认 `1`（显式 FTPS） |

上传逻辑在 `scripts/deploy-ftp.py`（只用 Python 标准库，无需装依赖），本地也能直接用：

```bash
npm run build
FTP_DRY_RUN=1 FTP_HOST=ftp.example.com FTP_USER=user FTP_PASSWORD=pass \
  python3 scripts/deploy-ftp.py --local build --remote /
```

- `FTP_DRY_RUN=1` 只打印将要执行的动作，不上传；确认无误后去掉再跑。
- 同步是**镜像**模式：本地没有的远端文件会被删除，避免旧页面和过期 hash 资源残留。
- `.well-known/` 与 `.htaccess` 默认保留（证书校验 / 服务器配置用），可用 `FTP_EXCLUDE` 调整。
- 是否重传按**远端文件大小**判断；要强制全量重传加 `FTP_FORCE=1`。

### Git LFS：图片等二进制必须走 LFS

跟踪规则写在 `.gitattributes`（`*.png` `*.jpg` `*.gif` `*.webp` `*.mp4` `*.pdf` 等），
目的是避免仓库随截图素材无限膨胀。

第一次使用这台机器上执行一次即可：

```bash
git lfs install
```

自检：

```bash
git lfs ls-files                                   # 被 LFS 跟踪的文件
git check-attr filter -- static/img/docusaurus.png # 应输出：filter: lfs
```

注意事项：

- **提交前确认本机跑过 `git lfs install`**，否则 filter 不生效、原文件会被直接塞进 Git，
  事后得用 `git lfs migrate` 重写历史。
- SVG / ICO 不纳入 LFS：体积小或是纯文本，留给 Git 管更划算，改了还能看 diff。
- CI 的 `build` job 已配 `lfs: true`。**删掉它不会报错**，只是拉到 130 字节的指针文本，
  构建出来的图片全是坏的，而且流水线还是绿的。
- Forgejo 侧需要在仓库 Settings 里允许 Git LFS（取决于实例管理员是否开放、配额多少）。
